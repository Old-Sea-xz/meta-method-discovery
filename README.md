# Meta Method Discovery

**不知道怎么入手，先找到合适的方法。**

一个面向 AI Agent 的专业方法发现与经验复用 Skill。你描述目标、困难和限制，它帮助 Agent 寻找相关领域的成熟方法，核对来源与适用条件，给出可以先试的一步；实际使用后，经你确认保存经验，供以后参考。

**发现方法 · 检查条件 · 小步验证 · 授权记忆**

## 它解决什么问题？

你可能知道自己想达到什么结果，却不知道这个领域有哪些现成的解题方法，更不知道该搜索什么术语。

- “动画动作很僵硬，我不知道怎么调整。”
- “工艺参数太多，全组合实验做不起。”
- “只有两页和三分钟，怎么解释我的研究？”
- “上次这个办法有效，这次条件变了，还能用吗？”

Meta Method Discovery 将这些描述转成可检索的问题结构，优先找领域内的方法，再按需要探索相邻领域。它不维护固定答案清单，也不要求用户先说出专业术语。

## 核心能力

| 能力 | 做什么 |
|---|---|
| 识别方法缺口 | 判断是否需要探索方法；翻译、事实查询和具体操作直接完成原任务 |
| 发现专业方法 | 寻找相关算法、原则、理论或框架，并追溯来源 |
| 检查适用条件 | 核对目标、数据、时间、工具、成本和必要假设，必要时拒绝推荐 |
| 给出最小试验 | 用回测、局部原型、对比或敏感性检查验证主推荐 |
| 复用个人经验 | 找回经确认保存的成功、部分成功与失败记录，再检查当前条件 |

## 看几个例子

### 1. 不知道术语，也能找到方法入口

> “我的动画动作看起来很僵硬，只有少量关键帧，应该先改哪里？”

**工作流示例，非实测效果承诺。** Agent先确认问题是节奏、间距还是动作衔接，再检索动画表现原则。若条件匹配，可以只选一段动作，尝试调整关键姿态间距或缓入缓出，说明依据并对比修改前后，而不是一次罗列整套动画理论。

你得到的是：**候选方法、为什么可能适合、先改哪一段，以及怎样比较结果。** 未实际验证前，不把建议标为成功。

### 2. 方法必须装得进预算

> “4种材料，每种初筛3次，另做2次对照，再给入选的2种各做3次确认。总预算18次，够吗？”

这是质量检查中使用的算术场景：

```text
原计划：4 × 3 + 2 + 2 × 3 = 20 次，超过预算。
备选安排：4 × 2 + 2 + 2 × 3 = 16 次。
```

Agent应指出超支，再讨论缩减初筛或调整后续确认的取舍。**16次只说明算术上可容纳；是否能把初筛从3次改成2次，仍取决于实验目的、误差和要求。** 用户若必须保留3次初筛，就不能偷偷改要求后宣称满足全部约束。

### 3. 记住成功，也记住成功的条件

> “上次三个人排三天值班安排成功了。现在增加夜班，但其中一人没有夜班资质，能直接沿用吗？”

**已运行的合成演示。** 程序实际枚举并检查旧班表，确认覆盖、可用时间和每人一次均满足后，以测试身份保存为 `SUCCESS`。独立新进程可以读取同一条 Markdown 经验。

按 Skill 的复用流程，Agent应解释：可以借用约束建模思路，旧班表却不能直接视为适用；增加夜班资质条件后需要重新求解。

**历史成功是参考，不是跳过当前检查的理由。**

### 4. 失败经验也值得留下

**已运行的合成演示。** 用训练数据 `[10, 10, 10, 10]` 的最后三点均值预测两个留出点，预测为 `[10, 10]`，实际为 `[30, 30]`。

```text
MAE = 20
演示预设验收标准：MAE ≤ 5
结果：FAILURE
```

失败记录保存了当时的数据条件与误差。新进程检索会返回失败提示；面对相似的需求跳升，Agent应先复核失败原因，而不是因为“上次用过”就直接沿用。

这个例子不说明均值法普遍无效。它展示的是：**经验库可以保留一次失败及其边界。**

另有“理解反馈改善、测验成绩未提高”的部分成功演示，见 [完整记忆案例与验证范围](docs/memory-showcase.md)。所有演示均使用合成数据；保存确认和培训反馈由测试夹具模拟，不是客户案例。

## 快速开始

### 安装

将仓库克隆到宿主支持的技能目录下，保留目录名 `meta-method-discovery`：

```sh
git clone https://github.com/Old-Sea-xz/meta-method-discovery.git
```

入口为根目录 [SKILL.md](SKILL.md)。按宿主要求重新加载技能或开启新会话；是否自动触发由宿主的技能发现能力决定。

### 使用

在支持显式 Skill 调用的宿主中：

```text
$meta-method-discovery
我需要分析没有评分的用户评论，不能调用外部LLM API。
请找合适的方法，先给一个低成本起点，并说明怎样验证。
```

支持自动发现时，也可以直接描述问题。提供目标、现有材料和硬约束，有助于缩小候选范围。

### 运行要求

- **方法发现**：宿主提供搜索、网页/文档读取与任务执行能力；不绑定指定模型或搜索服务。
- **个人记忆**：另需 Python 3.10+、PyYAML、持久文件读写权限，以及宿主提供可信用户身份和真实授权。

```sh
python -m pip install -r scripts/requirements.txt
```

没有搜索时须明确未核验；没有持久化能力时须报告未保存。

## 个人记忆：由你决定保存什么

```text
描述问题 → 发现与核验方法 → 应用/小试验 → 实际反馈
                                           ↓
                              展示拟保存内容 → 用户确认
                                           ↓
                               Markdown经验 → 下次检索与复核
```

每条经验是一个带 YAML Frontmatter 的 Markdown 文件，包含问题、方法、实际步骤、个性化调整、适用条件、反馈、来源和版本。支持新增、检索、更新、精确去重、删除及导出；近似记录的合并由 Agent 提案并获确认。

结果状态区分 `UNVERIFIED`、`SUCCESS`、`PARTIAL_SUCCESS`、`FAILURE`、`INCONCLUSIVE`。主观反馈、客观验证和 AI 推测分别记录；生成了方案不代表方法已成功。

为兼容项目旧名 Domain Method Finder，默认目录仍为：

```text
~/.local/share/domain-method-finder/memory
```

可用 `DOMAIN_METHOD_MEMORY_HOME` 或 CLI `--root` 指定 Skill 安装目录以外的可写持久目录。更名不会自动迁移或删除经验。文件为明文；用户路径隔离不等于操作系统级认证。接口和权限边界见 [个人记忆文档](references/personal-memory.md)。

## 验证与复现

在仓库根目录运行：

```sh
python tests/validate.py
python -m unittest discover -s tests -p "test_*.py" -v
python -X utf8 examples/run_memory_demos.py
```

发布前已运行：

| 验证 | 结果与范围 |
|---|---|
| 静态检查 | 6项通过：入口元数据、资源链接与测试资产等 |
| 记忆接口回归 | 18项通过：授权、保存、跨进程读取、更新、删除、隔离等 |
| 合成记忆演示 | 3个场景的存储断言通过，涵盖成功、失败和部分成功 |

演示结果生成到 `demo-output/`，活动知识库使用临时目录，不访问真实个人库。跨进程存储已验证；语义适用性仍由 Agent 复核，不是关键词搜索自动裁定。此处结果不证明所有模型、宿主或任务都能稳定正确执行。
