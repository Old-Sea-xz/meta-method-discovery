# 检索与证据记录

## 工具适配

使用宿主提供的搜索、网页读取、论文或文档工具，不要求某个 API、模型或另一个 Skill。优先遵守用户的工具和数据源偏好。若环境配置 AnySearch，遵循其接口；垂直领域搜索前先获取该领域子域（get_sub_domains），不要猜参数。其他工具按各自契约使用。

## 从问题到候选

1. 写出带关键限制的抽象问题，并识别本领域使用的专业叫法。
2. 搜“领域 + 问题结构 + established methods / review / textbook”，也检索中文专业同义词。综述用来发现术语，重要主张追到原始来源。
3. 从不同原理的方案中形成小候选集，同时查限制、失败条件和替代方案，避免只搜索“为什么有效”。
4. 域内不足时，用输入、输出、约束、机制相似性找邻域；远域只保留能说明机制映射的候选。
5. 核对方法名字、解决的问题、前提、适用边界。对决定推荐的主张读取原文，而非只看标题或摘要。

查询骨架（替换占位表达，不原样提交）：

- `[domain] established methods for [problem structure] under [constraint]`
- `[task] classical principles [professional term]`
- `[candidate] assumptions limitations validation original paper`
- `[domain] [desired outcome] methodology textbook`

## 最小证据记录

对关键候选记录：方法名；检索层；查询；来源标题、作者/机构、年份（可得时）、URL/DOI或书目与章节；实际读到的支持点；未支持的推断；访问状态。最终输出只保留对用户有用的部分。

优先：原始研究/方法作者资料 → 官方文档/标准与专业机构 → 可靠教材/综述。商业介绍和博客可以发现术语，不独立承担强效果主张。经典著作并非必须最新，但数据、软件、规则等时效信息应重新核查。付费全文不可读时说明只核对到哪一层，不能假装读过。

## 停止条件

通常先做一轮域内发现和一轮候选核验。已获得适配、可执行且有可靠依据的推荐便停止；出现关键证据缺口时才扩展或重写查询。无法弥补则明确不确定性。不要把“检索次数多”当质量指标，不为满足固定配额添加候选。

## 有限预算与环境判断

将已知的输出类型、数据量/质量、时序、工具和预算带入查询，不为未知条件造假。发现足够候选后，把剩余预算优先用于读取主推荐的关键来源；小预算通常先一轮发现再核查，不固定要求调用次数。无法访问时保留实际访问层级与缺口。

先发现宿主可用工具及已有 CLI，不因缺少同名 MCP 判断服务不可用；只按已读接口使用，不猜命令。用户指定资源受阻遵守其选择规则。资源路径相对 SKILL 目录解析。

来源访问层级为 full_text / abstract_only / search_snippet_only / unverified；另记具体支持与未支持的主张。即使读到全文也不能自动标记全部主张已核验。
