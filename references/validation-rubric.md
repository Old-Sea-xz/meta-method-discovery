# 候选验证与决策

## 六项检验

| 检验 | 必须回答 | 拒绝或降级条件 |
|---|---|---|
| 真实性 | 原始定义在哪里？来源实际支持什么？ | 无法核验只能留作未核验线索 |
| 相关性 | 解决的输入输出与当前目标是否相同？ | 仅同名或表面类比则排除 |
| 适用性 | 用户约束是否容许使用？ | 已知违反硬约束则排除 |
| 前提 | 数据、假设、工具和资源是什么？ | 缺失但可补则条件适用；不可补则排除 |
| 迁移有效性 | 哪种机制同构？什么不同？ | 只有比喻、没有可测试映射则排除 |
| 可操作性 | 接下来做什么、产出什么、怎样验收？ | 无法落地则不作为最终方案 |

## 状态

- **APPLICABLE**：来源可靠且主要前提已满足。仍需说明效果验证计划，不表示保证成功。
- **CONDITIONALLY_APPLICABLE**：方法已核验，但缺少可补充的关键条件；明确“若 X，则采用 Y”，列出检查 X 的方式。
- **NOT_APPLICABLE**：目标不匹配、硬约束冲突、关键假设已被否定或迁移不成立。

真实性未知是“未经外部核验”，不是第四种适用性等级，也不能冒充 APPLICABLE。可以讨论条件性可行性，但必须独立标明核验状态。数据不足不能等同于方法错误；方法真实不能等同于任务可用。

## 排序与组合

先过真实性与硬约束门槛，再按任务解决能力、证据、匹配、成本、可执行性、迁移风险作定性比较。不把强弱项机械加总为小数分数。只保留有实质优势的 1–3 个方案；没有合格方案时允许零推荐。

组合时交代数据流或工作流接口。例如先产生估计再进行决策，应说明估计的不确定性如何传递。两个框架只是换词重复同一功能时选一个。

## 迁移最小试验

写出来源机制 → 目标机制的映射，指出失效条件，选可观察指标和基线，先在低成本样本或原型上验证。经验原则不能被包装成因果定律，行业惯例不能当作性能保证。

## 主张与条件的边界

按关键主张核对支持内容：目录确认章节存在，不验证参数；摘要只支持实际读到的结论；厂商说明支持机制，不独立证明收益。访问 full_text / abstract_only / search_snippet_only / unverified 与主张是否受支持分开记录。数字、比较优势与默认参数若无直接支持，删去或明确示例性质；AI 推导和任务改编单独说明，用户正文保留关键来源链接与限制。

先核对决定选型的输出类型、数据质量、时序、工具、资源和风险，不默认有标签、稳定基线或标注预算。硬约束冲突直接否决；未知则条件适用。区分原方法规则、可迁移机制与当前改编。主线选择一个可执行起点，其余作为条件分支；不默认串联多种排序或建模框架。

## 交付前核对：从主张追到证据与条件

对决定推荐的主张和步骤，在内部逐条核对“主张/步骤 → 支持来源或任务输入 → 关键条件 → 检查结果 → 保留、降级或删除”。不必对用户展开审计表。

- 将一段话拆成可单独判断的主张；证明方法存在的来源不顺带证明其效果、参数或当前适用性。仅有自我判断不能补证据缺口。
- 必要条件逐项为已满足、未知或冲突；未知只能条件推荐，冲突排除。组合中的必要环节未通过时，整条链不能标 APPLICABLE。
- 涉及次数、费用或时间时实际计算总量和范围，包含重复、验证与重做；超预算则缩减或分阶段决策，不用“约”掩盖。算术通过不证明设计的专业有效性。
- 最终回答保留一个当前可做的起点；每个附加步骤必须解决明确缺口，否则删除或改为条件升级。缺决定性输入时不主动填入先验数字。

方法依据：[FActScore 原论文](https://aclanthology.org/2023.emnlp-main.741/) 将长文拆为原子事实逐项核实；[NASA 验证矩阵](https://www.nasa.gov/reference/system-engineering-handbook-appendix/) 将要求关联到验证方法。这里仅借用细粒度核对与可追溯思想；用于方法推荐的上述规则是本 Skill 的轻量改编，不是原方法已证明能提升本项目效果。
